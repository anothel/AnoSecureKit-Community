Security boundaries

Know what AnoSecureKit protects, and what it does not.

AnoSecureKit Community is a small C++20 utility library with OpenSSL 3.x as its only shipped production provider. It has not had an external security audit and is not a substitute for a full review in high-risk systems.

Read security model Report policy

Scope

AnoSecureKit provides byte encoders, SHA-256, HMAC, HKDF, random bytes, AES-256-GCM packets, and chunked file sealing through a private provider boundary. OpenSSL 3.x is the only shipped Community production provider; the external seam is build-tree-only.

Audit status

AnoSecureKit has not had an external security audit. Use separate review for high-risk systems.

Support status

Security support is EOL with archival response only. No version has an active maintenance commitment or response SLA. Reopening requires a new explicit product decision.

Reports

Do not report vulnerabilities through public issues. Use GitHub Security Advisories or a private maintainer contact path. Submission does not promise a response, fix, advisory, or release.

What AnoSecureKit does not provide

  • Custom cryptographic primitives.
  • TLS, networking, or secure key storage.
  • Guaranteed memory erasure.
  • Password hashing for account authentication.
  • Caller-selected algorithms or nonces.
  • Protection from compromised hosts, filesystems, shells, or build tools.
  • KCMVP, FIPS, certification, validation, or security-audit claims.

Authentication rules

One-shot decrypt returns plaintext only after authentication succeeds. Incremental `packet_decryptor::update()` can return unverified plaintext before `finalize(tag)`, so callers must buffer it until final authentication succeeds.

Wrong keys, wrong AAD, wrong passwords, modified ciphertext, modified nonces, and modified tags use generic authentication failures.

File output safety

Published v0.4.0 generic CLI output can create key or plaintext files with mode 0644 under a POSIX umask 022. The unpublished maintenance snapshot uses exclusive temporary-file creation and mode 0600; that correction has not been released. Stream output and CLI --out - cannot be rolled back, so callers must trust output only after the command exits successfully.

Password-based file sealing

`SKP1` reads password bytes exactly as supplied. AnoSecureKit does not trim, normalize, prompt, read environment variables, or define password quality rules. Current `SKP1` uses fixed scrypt parameters.

OpenSSL dependency

AnoSecureKit uses the default OpenSSL library context and provider configuration already active in the process. Applications that require custom providers must configure OpenSSL before calling AnoSecureKit.
